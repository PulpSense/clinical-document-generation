# Separate agent drafting from deterministic delivery

Agent drafting uses versioned, contract-defined Drafting Batches rather than one agent per document or a fixed agent count for every document. Prospective and Ambispective runs first launch three Protocol batches—Foundations, Operations, and Analysis and Oversight—plus one unified ICF batch; after Protocol Foundations passes, one narrow PRS narrative batch drafts only the brief and detailed descriptions. Retrospective runs launch only the three Protocol batches. The topology stays stable during a run, and retries target failed section IDs within their existing batch.

Subagents return structured Section Drafts from only the relevant Approved Source-of-Truth fields, Document Section Contracts, Fixed Clinical Boilerplate, and any explicitly relevant accepted Section Drafts; they do not receive the raw intake packet or unrelated drafts. One unified ICF batch preserves the participant-facing voice, while Python retains all PRS XML structure, mapping, repeated blocks, ordering, and validation. After deterministic assembly, one package-wide read-only verifier checks content and cross-document consistency and another checks every rendered Protocol and ICF page; neither silently rewrites content.

Python scripts own approval state, deterministic contract-order merging, assembly, renderer invocation, retry selection, attempt limits, Delivery Gates, and atomic release. A failed Required Generated Section or rendered layout receives three total attempts, after which delivery blocks with a Repair Report. The final Cross-Document Consistency Gate compares every required output with the Canonical Approved Source.
