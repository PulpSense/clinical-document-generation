# Deliver review copies when a complete candidate has unresolved findings

The workflow has two document outcomes. `passed` publishes a complete, verified Branch Document Set in `output/` as client-ready. `review_required` exposes the complete, hash-matched candidate in `review-output/`, prefixes every filename `REVIEW-ONLY-`, and includes `findings.json`. Review copies are documents for correction, not approved client deliverables. Approval, source identity, file integrity, and the exact Branch Document Set remain prerequisites for both outcomes.

Word counts are reference drafting goals. A one-word excess cannot prevent construction or publication when the content and rendered layout pass. Editorial repetition and duplicate words are retained warnings. Missing required source facts, unsupported or strengthened clinical claims, missing or altered consent safeguards, unreadable output, malformed PRS structure, and stale publication evidence still prevent client-ready publication. Once a complete hash-matched candidate exists, unresolved findings produce `review_required` rather than an empty result.

The six production modules retain one workflow entrypoint. Every future finding producer must declare whether its finding is a warning or requires review; the publication path must retain the finding and never silently relabel an unreviewed candidate as passed. The offline blocker inventory detects changes to these producers, while replay and varied-input tests assess their behavior. Independent reviewers retain authority over clinical meaning; their approval is never fabricated from a deterministic check.
