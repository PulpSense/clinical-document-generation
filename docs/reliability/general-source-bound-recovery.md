# General source-bound construction recovery

Owner-authorized scope: the current conversation's request to recover from
source-resolvable construction defects across different inputs and all three
study types. Part of GitHub #71/#89. Starting commit: a6a7be5.

## Required behavior

- An independently reviewed construction defect with an exact native location
  and approved evidence receives a constrained AI correction request, rather
  than only repeating the original faulty projection.
- Reuse the authenticated construction handoff, immutable approval snapshot,
  archived candidate hashes, producer identity and accepted-response checks.
  Persist accepted corrections and reapply them after every rebuild.
- Native XML scalar edits preserve element ordering, repeated block counts,
  attributes and identifiers. Replacement text is grounded in exact scoped
  approved scalar values. Removing an unsupported generated value does not
  authorize removal of an explicitly supplied fact.
- Code-owned DOCX metadata fields and positively registered display prose may
  be corrected through the same handoff. Protected template language, Sterling
  merge tags, signatures and arbitrary document paragraphs remain outside it.
- Validate rebuilt structure and then require fresh complete independent
  content and every-page review. A proposed or accepted edit is not clinical
  approval. Material concerns never inherit harmless-presentation disposition.
- Material construction correction allows up to three proposals per stable
  target inside the persisted operation deadline. No new operation is launched
  automatically. Invalid requests, stale evidence and ungrounded proposals
  cannot grant publication authority.
- Explicit structured person components govern their boundaries as a coherent
  group; inferred components use only the remaining consistent full-name text.
  Compound given names and surnames do not duplicate inferred middle names.

## Coverage and limits

Exercise actual public approval/generation/recovery/delivery across all five
branch/template families. Inject construction faults in contacts, dates,
quantities, titles and generated prose; verify repaired output and unchanged
approved evidence. Pair success with stale, malformed, ungrounded, out-of-scope,
identity-changing and tampered corrections. Vary source representations through
public XML generation, with independent expectations for every person role.

Narrative sections and schedule relationships retain their existing scoped
redrafting/source-interpretation routes. The new field editor repairs existing
scalar fields; structural node insertion/deletion and invented clinical decisions
are outside it. Ambiguous locations or genuinely conflicting source facts still
need resolution. Controlled local reviewers/renderers establish mechanics, not
live clinical judgement or Linux page quality. The ten-input Hermes campaign is
still required as external reliability evidence. No full suite, paid corpus or
Linux dependency changes are authorized by this implementation.

## Review and validation record

Both required review axes completed. Standards review identified whole-paragraph
formatting loss and an unhandled stale XML exception; both were fixed and covered
through public delivery tests. Spec review identified repeated-value localization,
overlapping replay/retry identity, and material quantity repair gaps; all were
fixed. Both re-reviews found no further actionable issue.

XML proposals now undergo the existing objective XML checks before acceptance.
Errors in edited fields or newly introduced validation failures reject the proposal
through the same bounded handoff. A rebuilt accepted overlay that nevertheless
fails structural validation stops cleanly rather than repeating reconstruction.
Retry accounting uses native field identities across overlapping quotations;
replay order uses the authenticated archived accepted-record inventory.

Overlapping accepted-edit replay is exercised directly at the native application
boundary. The complete delivery tests use actual workflow preparation, approval,
construction, repair handoff, review binding and delivery, with controlled model
responses and page-render evidence. They do not simulate two successive reviewer
quotations of overlapping XML subtrees in one delivery operation.
