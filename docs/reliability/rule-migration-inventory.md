# Condition authority migration inventory

Spec #91; foundation #92. This is a migration map, not a declaration that all
blocking conditions have behaviorally verified recovery. The legacy
`blocking-checks.json` remains a **function fingerprint inventory**. Its nested
and dynamically emitted conditions are provisional until enumerated and exercised
under #102. Passing that inventory does not certify recovery.

| Producer families / surfaces | Authority to distinguish | Migration owner |
| --- | --- | --- |
| Protocol rendered lexical source coverage | Semantic evidence; numerical identity failures remain separate | #92: `protocol.source-coverage.lexical`, all three Protocol branches |
| Protocol timeline, short body, source-mode, eligible/visit phrases, repetition, citation/date representations, metadata phrases | Separate per-condition objective facts from representation proxies | #93 |
| Advarra/Sterling rendered clauses, privacy/consent phrases, numeric/citation proxies | Exact required legal text versus semantic study facts | #94 |
| Intake/parser/source readiness before approval | Inferred conflict versus missing mandatory source or approval trust | #95 |
| Missing sections, ambiguous or absent native addresses, nested recovery routing helpers | Execution/localization versus a clinical omission | #96 |
| DOCX construction/body/table/header/footer editors and pre-review reconstruction | Native integrity/protected language versus editable generated content | #97 |
| XML scalar/derived mappings, node/collection structure and schema | Approved relationships and native validity versus formatting | #98 |
| Workflow stopping, progress observation and dynamic recovery plans | Transport/capability state versus adjudicated substantive defect | #99 |
| Reviewer response validation, renderer/page checks, nested/helper findings | Authenticated review evidence and execution versus presentation judgment | #100 |
| Publication, complete package, byte checks and notices | Non-waivable trust/integrity versus resolved/unresolved review concerns | #101 |
| Remaining direct, nested, dynamic and pre-review finding producers in all scripts | Enumerated rule records with executable per-condition evidence; reject unregistered conditions | #102 |

The executable foundation is `scripts/rule_authority.py`. Each migrated condition
has a stable ID/version, producer, applicability, authority, evidence inputs,
repair/adjudication routes, verification obligations and explicitly bounded test
evidence. Production findings carry the rule contract digest. Unknown/stale
identities receive no semantic waiver. Legacy conditions remain on their existing
routes until individually migrated; mixed producers must not be blanket reclassified.

The #92 tracer exercises controlled public prepare/approve/generate and exact-byte
Desktop confirmation across Prospective, Ambispective and Retrospective. Its
renderer and review/model adapters are controlled doubles. This is local control-flow
and binding evidence, not live Hermes judgment or page quality certification.
