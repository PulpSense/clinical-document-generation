# Render Assurance capability resolution

Activation provisions a version-local LibreOffice renderer, a version-local PyMuPDF page renderer, and approved compatible Liberation fonts. It then verifies package hashes and performs a real DOCX-to-PDF-to-PNG smoke using those release-owned renderers before atomically replacing the active skill. A failed candidate never displaces the previous verified release. Normal document generation remains read-only.

`generate` constructs the complete branch candidate before resolving runtime capabilities. It tries Microsoft Word, installed LibreOffice, Pages, and the verified release-local LibreOffice runtime; tool failures fall through, while a genuine defect remains bound to the renderer that exposed it. PDF rasterization independently falls through Poppler, MuPDF, Ghostscript, ImageMagick, and PyMuPDF.

Font probes return available, missing, or unknown. Unknown inventory preserves the requested font and relies on render evidence. Proven missing fonts use the explicit release-owned Liberation mapping; heuristic host substitutions are not accepted. The DOCX bytes, substitution, renderer, page renderer, and every failed attempt are recorded. Capability smoke is not client-ready evidence: final delivery still requires deterministic validation and actual image inspection of every exact rendered page. A genuine defect applies an auditable pagination repair without changing template margins, spacing, fonts, or content, then rerenders on the renderer that exposed it. If the 30-minute ceiling arrives with a genuine unresolved defect, the complete candidate remains internal and the atomic client package remains unpublished.
