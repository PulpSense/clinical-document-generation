# n8n Prospective Protocol, ICF, and XML Branch

Use this reference when `meta.study_type` is `Prospective`.

Read `references/starred-fillout-required-inputs.md` first. Its 35 starred fields are the only prospective source-input blockers.

## Branch Shape

The existing workflow routes `selectYourTypeOfStudy = Prospective` through this sequence:

```text
Protocol Type
  -> Introduction
  -> Population Variables
  -> Study Design & Methods
  -> Procedures & Assessments
  -> Visits Table
  -> Statistics & Sample Size
  -> ICF Visits
  -> Risks & Benefits
  -> Outcomes
  -> Build Location Array
  -> Set Protocol Fields
  -> Protocol DOCX replacement
  -> XML JSON generation
  -> ICF DOCX replacement
```

The skill must mimic that sequence locally:

1. Draft or update `reference/study.reference.json` from source material.
2. Run the source-input preflight, generate the named source Markdown, and complete the source Markdown approval loop.
3. After approval, generate each module output below from the approved source inputs and save it under `generated.protocol`, `generated.icf`, or `generated.xml`.
4. Run `scripts/build_n8n_prospective_fields.py --run-dir <run-dir>` to populate the flat n8n variables under `template_fields`, then render final outputs.

## OpenAI Module Outputs

These are the variables generated by the prospective OpenAI nodes in n8n. Keep the exact camelCase/snake_case names where possible so future template mapping is straightforward.

Do not place these generated variables in the source Markdown. It should contain only the source inputs that drive these modules.

| n8n node | Save under | Variables | Used by |
| --- | --- | --- | --- |
| `Introduction` | `generated.protocol` and `generated.icf` | `icfPurpose`, `shortTitle`, `introduction`, `investigatorFirst`, `investigatorMiddle`, `investigatorLast`, `coordinatorFirst`, `coordinatorMiddle`, `coordinatorLast` | Protocol title/introduction, ICF purpose, XML investigator fields |
| `Population Variables` | `generated.protocol` and `generated.icf` | `populationShort`, `populationLong`, `inclusionCriteria`, `exclusionCriteria`, `minimumAge`, `maximumAge`, `icfEligibilityBullets` | Protocol population/criteria, ICF eligibility, XML eligibility |

## XML Variables

The n8n prospective branch builds XML from the same `Set Protocol Fields` output. Keep these values available in `template_fields` even before the final XML template is provided:

| Field | XML use |
| --- | --- |
| `startDate` | Study start date |
| `endDate` | Study end date |
| `lastFollowUpDate` | Last follow-up date |
| `primaryCompleteDate` | Primary completion date |
| `verificationDate` | XML verification date |
| `primaryOutcome` | JSON string for primary outcome array |
| `secondaryOutcome` | JSON string for secondary outcome array |
| `enrollment` | Anticipated enrollment |
| `minimumAge` | Eligibility minimum age |
| `maximumAge` | Eligibility maximum age |
| `groupsNumber` | Number of groups |
| `investigatorFirst`, `investigatorMiddle`, `InvestigatorLast` | Investigator name parts |
| `coordinatorFirst`, `coordinatorMiddle`, `coordinatorLast` | Coordinator name parts |
| `locationArray` | JSON string of study locations |
| `regulatedDrug`, `regulatedDevice` | FDA regulated flags rendered as Yes/No |
| `interventionType`, `interventionName` | Intervention fields |
| `samplingMethod` | Sampling method derived from single-arm vs multi-arm design |

The old n8n `Generate XML JSON` node used a simplified PRS shape and hardcoded values that the client corrected manually. For final ClinicalTrials.gov PRS XML, do not use that old JSON shape as the output structure. After this n8n mapper runs, run:

```bash
python3 scripts/build_prs_xml_fields.py --run-dir <run-dir>
```

Use `references/prs-xml.md` for the canonical PRS template, required reviewer-controlled PRS fields, repeated block counts, defaults, and XML validation.

## QA Rules

- Do not generate final prospective outputs until `build_n8n_prospective_fields.py --check` reports no blank required fields.
- For prospective runs, `build_prs_xml_fields.py --check` distinguishes missing PRS values from blocking missing starred inputs. Nonstar PRS administration gaps remain visible but do not trigger intake follow-up. Do not present XML as technically valid unless `validate_prs_xml.py` passes after rendering.
- Keep missing optional administrative fields blank rather than inventing them.
- Preserve n8n typos such as `sponsortName`, `sponsortAdress`, `ibrName`, `ibrAdress`, and `studyCordinatorName`; copied templates may use those exact names.
- The ICF and XML fields must come from the same reviewed `study.reference.json` as the protocol.
